# 单据排版打印台

面向飞书/Lark 多维表格的单据排版与打印插件。它使用飞书官方 Base SDK 读取当前勾选的主记录及关联明细，在浏览器内生成 A4 预览，并打开独立窗口完成打印或“另存为 PDF”。

> 隐私优先：社区版没有接收单据内容的业务后端。客户、金额、银行和产品明细不会发送给项目维护者。

## 主要功能

- 读取多维表格当前记录或用户勾选的多条记录
- 展开主记录关联的明细记录
- 自带一个“测试模板（形式发票）”，用于检查取数、关联明细和打印窗口
- 支持导入旧版飞书导出的 `.txt` 模板及兼容的 `.json` 模板
- 支持绑定主表、明细表、关联字段和单据字段
- 支持公司信息、标题、条款、列宽、字号和页边距调整
- 在可拉伸的独立窗口中检查单据、打印或另存为 PDF
- 自定义模板可保存、复制和删除，并且只保存在当前浏览器
- 开发模式提供完全虚构的演示数据

## 在线地址

- 飞书插件服务地址：<https://eason2795.github.io/feishu-bitable-print-plugin/>

## 在飞书多维表格中使用

1. 打开目标多维表格。
2. 进入“多维表格插件”→“自定义插件”→“新增插件”。
3. 名称填写“单据排版打印台”。
4. 服务地址填写上面的 HTTPS 插件地址。
5. 打开插件，进入“模板管理”。
6. 点击“导入模板文件”，选择旧版导出的 `.txt` 或兼容 `.json` 模板。插件会优先识别当前主表，并通过关联字段找到明细表；无法确认的项目会在编辑器里明确提示。也可以复制测试模板开始设置。
7. 回到“排版打印”，在表格中勾选记录，或点击“选择要打印的记录”。
8. 检查 A4 预览后点击“在新窗口打印”。新窗口可调整大小，并可选择打印机或“另存为 PDF”。

独立打印窗口显示的是点击时的本次快照。回到飞书修改勾选或数据后，请重新打开打印窗口；关闭窗口后，快照即清除。

自定义插件默认只对创建者可用。面向外部客户发布时，应提交飞书多维表格插件市场审核，客户即可从市场安装，不需要手动填写服务地址。

## 首次模板设置

系统只保留一个“测试模板（形式发票）”，它的表名和字段名只是虚构示例。正式使用请优先导入自己的模板文件，并按当前 Base 的实际结构设置：

- 主表：保存要打印的单据主记录
- 明细表：保存商品、数量、单价等明细
- 关联字段：主表中连接明细表的字段
- 主字段：单号、日期、客户、总计、条款、银行信息等
- 明细字段：品名、规格、数量、单位、单价、小计等

模板状态显示“可打印”后，再回到表格勾选记录。若当前表与模板主表不一致，插件会直接显示需要切换到的表名。

自定义模板可在左侧模板列表或“模板管理”卡片中删除。删除前会再次确认；系统测试模板不会被删除，需要修改时先复制为自定义模板。

模板文件最大 2 MB，只在当前浏览器中读取，不会上传到项目维护者的服务器。若文件不是旧版飞书排版模板、内容损坏或缺少页面排版结构，插件会明确拒绝，不会自动套用测试版式。

从 0.5.x 升级时，已经导入或复制为自定义模板的内容会继续保留。若升级前仍直接使用商业发票、装箱单或采购单内置项，插件会暂停打印并提示重新导入旧模板，或由用户明确改用测试模板。

若曾在 0.6.0 中保存过“排版已导入但数据源未配置完整”的模板，0.6.1 会在当前浏览器自动恢复 PDF 版式，并在能够确认当前主表、关联字段和明细表时自动补齐；无需删除模板或重新上传，模板数据也不会离开浏览器。

## 是否需要服务器

基础功能不需要自建业务服务器：

- 飞书官方 SDK 负责读取当前用户有权访问的数据
- 浏览器负责排版、独立窗口和打印
- 自定义模板保存在浏览器本地
- 项目只需要一个可被飞书访问的 HTTPS 静态页面

GitHub Pages、Cloudflare Pages、Vercel、对象存储加 CDN 或自有静态服务器都可以承载这个页面。若以后增加付费授权、远程停用、云模板或跨设备同步，才需要额外的授权或业务后端。

## 本地开发

需要 Node.js 20 或更高版本。

```bash
npm ci
npm run dev:host
```

浏览器打开 `http://localhost:5173/?demo=1` 可查看虚构演示数据。生产环境读取飞书失败时不会自动套用演示数据，避免误打印。

提交前运行：

```bash
npm run lint
npm run build
```

## 部署

### GitHub Pages

仓库自带 Pages 工作流。推送到 `main` 后，在仓库 Settings → Pages 中把 Source 设为 GitHub Actions，即可自动构建并发布 `dist/`。

### 其他静态托管

执行：

```bash
npm run build
```

将生成的 `dist/` 部署到任意支持 HTTPS 的静态托管服务。Vite 使用相对资源路径，可部署在域名根路径或子目录。

若使用项目自带的容器示例：

```bash
docker compose up -d --build
```

本机默认访问 `http://设备地址:18087/`；填入飞书时仍需配置可公开访问的 HTTPS 地址。

## 历史 Chrome 实验版

0.2–0.4 版本曾提供 Chrome 侧栏实验。Chrome 扩展不能单独读取飞书勾选数据，仍必须依赖飞书插件，因此从 0.5.0 起不再作为推荐产品路径。已有测试环境可参考 [历史 Chrome 扩展说明](docs/CHROME_EXTENSION.md)。

## 技术结构

- React + TypeScript + Vite
- 飞书 Base JS SDK
- 浏览器原生打印与“另存为 PDF”
- localStorage 保存自定义模板
- GitHub Actions 自动验证与部署

关键文件：

- `src/feishu.ts`：读取当前 Base、勾选记录、关联明细和字段结构
- `src/piConfig.ts`：系统测试模板与字段映射
- `src/printDocument.ts`：生成可打印 HTML
- `src/localPrint.ts`：打开独立打印窗口和系统打印
- `src/templateStore.ts`：浏览器本地模板存取
